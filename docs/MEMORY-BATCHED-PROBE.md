# Separate bounded batch fingerprint probe

This is a separate ReShade add-on; it does not replace `opengl32.dll`, hook drawing, use a kernel driver, or change Secure Boot. No scan runs until a PID-, nonce- and batch-specific trigger file exists in `%TEMP%`.

There are at most four batches per loaded process, each with at most eight 64 MiB read-attempt slices (512 MiB per batch, 2 GiB total), a 10-second cap per slice, four-millisecond waits per 64 KiB chunk and two-second pauses between slices. A later batch has a separate ready file and needs a separate trigger; no batch starts automatically. The cursor and intentional boundary overlap are retained in memory only during the current process lifetime. Restarting BlueStacks or unloading the add-on resets it; never reuse a cursor in a different process. The final cumulative byte count includes overlaps, inaccessible or changed pages, and any read failures. Stop on first fingerprint match, cancellation, completion, allocation failure or no progress. A worker is cancelled and joined on add-on unload.

The 64-byte target is the first bytes of the previously hash-matched installed ARM64 `libil2cpp.so`; it is not a player or team list. A host match may be a cache or data copy and is not proof of guest mapping. A negative result is inconclusive, even after four batches: the guest library may be paged, transformed, remapped, not present in the host's readable ranges, or outside scanned bytes. No player addresses, lists or memory dumps are produced. Scan attempts may affect performance or trigger game enforcement. Install and initiate each batch only with user authorization, while the game is in the requested state. Scope should not be raised without renewed consent.

Ready: `chams-batch-ready-<pid>-<token>-<batch>.txt`. Trigger for the corresponding exact ready: `chams-batch-trigger-<pid>-<token>-<batch>.flag`. Result: `chams-batch-result-<pid>-<token>-<batch>.txt`. Result lines include counts, host candidate and cursors, never raw memory. Ready files can remain after unload; use log evidence plus current PID and latest token, and refuse old process IDs/results. Trigger files are created with CREATE_NEW; avoid duplicate execution.

Builds through GitHub Actions on Windows. Tests: existing scanner range/overlap/cancellation fixtures; test-only small batches exercise all four explicit triggers, no automatic progression, cursor handoff, hard batch cap, and in-flight cancellation. The test-only build has smaller budgets and is not the artifact. None of these tests proves access to the Android guest address space or that a detected candidate represents the live library.
