# Runtime capture implementation — foundation only (not a tracking build)

Status: **not wired into ReShade**. Do not ask players to capture rounds with this code; the present DLL will not create these files. The previous local own-tracker experiment is intentionally not included in this branch, so this work does not add player or wall exclusion rules.

## Implemented standalone foundation

`source/chams_capture.{hpp,cpp}` provides a C++17 recorder and a preliminary context/frame correlator. It has a bounded queue, asynchronous single writer, JSON Lines, session start/stop markers, monotonic relative timestamps and a wall-clock start in Unix milliseconds, rotated parts, a final JSON summary, explicit overflow, oversize, allocation and write-failure counts, queue high-water mark and cumulative producer enqueue duration. Disk operations are performed without the producer mutex held. Thread IDs and context generation IDs are numeric and do not expose native addresses. A session directory is created exclusively and never overwritten. Failure to write the summary itself is only available via in-process status; a crash or full disk may leave no complete summary. Records in an incomplete last part may be truncated. `written` means accepted by the stream, not durable on physical storage. Flush happens periodically and at stop, not per draw. The sequence number may have gaps when events are lost. The final completeness flag is false for any reported loss or I/O failure.

The correlator maps opaque native context handles to session-local generations and assigns a context-local ordinal to activity between successful presents. A failed present does not advance the ordinal. This is a starting abstraction, not a validated definition of game frames: multiple drawable surfaces, context migration, make-current failure, share groups, overlapping presents, starts in the middle of already-live contexts, destruction/reuse and stopping with open frames still need to be handled or explicitly reported. The session owner must instantiate a fresh correlator for every capture. It currently emits an end event for context destruction but does not close all open contexts at stop. The event body is trusted, internally generated JSON; never feed raw driver strings into it without proper escaping and bounds.

`tests/run_chams_capture_tests.py` compiles and runs the standalone core, parses every record, exercises four concurrent producers, 4,000 interleaved context-frame sequences, failed present, native-handle reuse, JSON integrity, rotation, overflow, and forced output failure on Linux. An additional synthetic run with 408,004 draw records was executed locally; producer-phase mean enqueue time includes mutex waiting and is **not** an in-game FPS measurement. ThreadSanitizer completed successfully on the same standalone stress test in this Linux sandbox. These tests do not cover GL, Windows DLL loading, actual render-thread overhead, device drivers or pixels. The workflow adds Linux and Windows standalone-core tests, but the Windows job has not yet been run.

## Required integration before a release

1. Integrate capture start/stop into the existing UI with unique session directories, visible running/draining/error states and path copying. Preserve existing INI semantics; do not persist an active capture as a setting. Stop must safely drain without blocking the render thread indefinitely; guard shutdown/DLL unload and concurrent UI operations. Report disk-full and inability to create the summary.
2. Instrument WGL create, make-current, release, deletion and share-group/surface lifecycle, capturing results only after API success. Associate `g_opengl_context` with a generation without pointer reuse confusion. Hook both normal and layer/multiple swap variants where they apply, recording before/after swap with result, surface identity and thread. Define what frame start/end means for contexts with no presents and offscreen render passes. Handle in-flight events at stop.
3. Inventory every GL draw route actually intercepted by this ReShade build, including direct, base-vertex, base-instance, range, indirect and multidraw variants. Existing Chams wraps six entry points; tracking only them is not comprehensive. Track original game draw activity independently of extra ReShade/Chams replay passes and addon interception. Preserve addon behavior and hook ordering. For indirect GPU commands where counts cannot be read without stalling or modifying state, mark values unavailable; do not silently skip them.
4. Correlate the existing actual classification and application decisions on wrapped calls, including menu/master/budget/primitive gates, strict/wide tokens, wall hints, draw information, own-tracker before/after state and reset reasons, overlays/fallbacks, depth/write/blend state, settings changes and lifetimes. Capture relevant program/uniform metadata and object/camera matrices without calling state-mutating code or relying on stale caches. Nonwrapped calls must be marked as not classified, not falsely treated as rejected. Enumerate each unavailable field.
5. Provide a deliberate user marker (and wall-clock correlation, noting clock skew) for linking a scene/screenshot to nearby presents. A stream of GL draws cannot prove which pixels belong to a wall or player; projection origins are not object bounds. Avoid any claim that a visual object is automatically identified. Explain gaps caused by overflows, missing hooks, GPU-generated draws and logging-induced timing changes.
6. Address record construction overhead and contention, bound memory in bytes as well as records, validate strings and non-finite floating-point JSON, and measure tracing on real Windows GL/gameplay against tracing disabled. Consider per-thread batches and program-metadata deduplication. Test high throughput, capture start/stop racing render/present, disk full, rotation, abrupt exit, session restart, thread exit, context migration/destruction and shutdown. Detect all drop and I/O reasons. Ensure no sensitive unrelated data, process-wide memory, or actual asset contents are collected.
7. Run all Windows and Linux jobs for the exact commit, retrieve and digest-verify the x64 Release artifact. Do not deliver an earlier or incomplete DLL as the tracking build. Only after the complete capture is proven ready should the user record two rounds.
