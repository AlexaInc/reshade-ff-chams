# Border reference: reversed-depth experiment

Reference `TST/opengl32.dll.decompiled.c`, SHA-256 `6179128a15803bb40edbbe8ef0fb56f44ff8734c151793e85b91433b354fcbc5`; binary `TST/opengl32.dll`, SHA-256 `551417d49bed807344e6d6d2fd085b509efdce2c1d245008fd81a94945c5e753`. Analyzed statically, not loaded or executed. The decompiler associates Border Chams with `DAT_1803afe7f` and hook `FUN_180096010`. Binary disassembly around `0x18009647c` confirms call sequence and argument registers; the pointer-name table establishes dispatch `0x1803d3fd8` as `glDepthRangef` and `0x1803d4678` as `glLineWidth` (the name table and GL dispatch table have matching 8-byte offsets relative to `glBlendColor`). This is stronger than interpreting undeclared Ghidra call types alone.

For matching `GL_TRIANGLES`, count >= 1000, `_CharaLightIntensity`, reference first calls the original draw, then in the Border branch approximately:
1. `glDepthRangef(1,0)`, line width 1, enable blend with constant-color/one-minus-constant-alpha, blend color black; draw original triangle mode with the inherited depth test/write/func.
2. `glDepthRangef(1,.5)`, set outline color, draw indices as `GL_LINES` (not `glPolygonMode(GL_LINE)`).
3. Restore depth range 0..1, disable depth testing, enable blending with ONE/CONSTANT_COLOR and black constant color, draw original triangles, then re-enable depth testing and disable blend. It does not restore all the prior state and does not replay at presentation.

The prior candidate (87114ea) implemented only depth-independent color coverage. The user confirmed BorderCompat was ON and reported default-kit fill still failed. Therefore do not claim that candidate solved the issue.

This revision adds a *different*, explicitly experimental reference-inspired **fill-only** depth seed when Direct, ThroughWalls, BorderCompat and Glow are enabled, only if the original draw has both depth test and depth writes on. It runs after the existing claim/restore: saves/restores GL state, performs a color-masked triangle redraw using `GL_LEQUAL` and reversed range (1,0), and intentionally leaves the new depth-buffer contents in place. It does not copy the reference's line primitive or non-restored GL state. Wire and Stroke do not get this seed. With default depth mapping, an original mesh fragment at z=.8 produces reversed depth .2; a later LEQUAL wall at z=.4 then fails. Real shaders may write `gl_FragDepth` and walls may render differently. A later wall closer than .2 or with depth disabled still covers it. A later body part or other scene object can also be blocked. Transparent/no-depth-write meshes are deliberately not seeded; no matching or identity problem is addressed. The option may tint open pixels and changes depth throughout the silhouette; leave it OFF if artifacts occur. Source does not identify the default-kit mesh or Gloo Wall in the supplied trace, so this is a testable hypothesis, not a proven cause or verified fix.

Tests: stateful mock executes actual code, all four fill modes, fill/wire combination, flag gates, skips for original no-depth-test/no-depth-write, and GL state restoration. A real Mesa/EGL offscreen pixel model demonstrates the simplified late-wall mechanism, closer-wall/depth-disabled failure, and a later-part occlusion side effect. Neither test reproduces BlueStacks/game shaders, FBO handoffs or real Gloo Walls. The capture has no screenshot/marker to identify which draw covers which pixel. Exact-commit Windows x64 build requires Actions and separate in-game A/B testing before any claim of success. No automatic installation or replacement is included.
